# Reclaim QR：重新获得 60 秒

## 上线步骤

1. 在 Supabase SQL Editor 执行一次 `supabase/migrations/0025_renew_digital_claim_window.sql`。
2. 重新部署网站。此改动同时包含主网站的 API 和打包的数字游戏界面，仅刷新旧部署不会生效。
3. 完成一局游戏，等倒计时减少后点击 **RECLAIM QR**。显示 **RENEWING…**，后台成功后恢复约 60 秒。
4. 用手机扫描同一个 QR 登录领取，确认排行榜只增加一次分数。已打开的手机链接仍可使用，无需更换 QR。

没有执行线上 SQL；本次已完成代码和本地测试。执行迁移前，线上后台仍保留旧的有效期限制，续期不能完整工作。

## 行为

- 普通加载、自动重试不延长时间；只有手动点击 Reclaim 才续期。
- 沿用同一二维码和比赛结果。创建时间不改，新增 `renewed_at` 记录最近续期，后台每次给予 60 秒。
- QR 状态查询、手机领取页、数据库实际领取函数统一使用续期后的有效期。
- 领取与续期锁定同一行，已领取的码不能重新开放，不改变每活动一次及胜者领取规则。
- 只有服务器服务账号可执行续期函数。失败不会伪造一个新的前端 60 秒。
- 续期请求中禁止重复点击，并忽略旧状态查询响应，避免旧过期状态覆盖新期限。续期仍受请求超时限制，不会让终端永久停留。
- 若倒计时已经结束并自动回到首页，不能从该结果界面再点续期；应在界面离开前操作。

## 检查

- `npm run lint`、`npm run build`、`npm run test:digital-games` 通过。
- `npm run test:digital-claims`：实际路由配合本地 PostgreSQL（PGlite）通过普通重试不延时、续期后有效、保存原结果与创建时间、已领取不重开、禁止学生直接续期及重复领奖限制检查。
- `scripts/verify-digital-performance.mjs`：模拟后台将 20 秒窗口续为 60 秒，确认按钮、请求与显示倒计时同步，同时保留游戏加载及 QR 回归检查。浏览器请求经过模拟，没有创建真实积分。

迁移只新增有效期记录并更新领取函数，不清空资产、提交或排行榜分数；无需关闭 RLS。
