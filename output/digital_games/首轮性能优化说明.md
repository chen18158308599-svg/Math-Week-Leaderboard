# 数字游戏首轮性能优化

本轮优先减少加载、音频和大屏绘制负担，游戏规则、提示、得分与领分数据库逻辑未修改。

## 已完成

- 删除 KNN、Number Sequence、Planarity 的背景音乐播放与加载接入；Number Sequence 的音乐切换、淡入淡出定时器一并移除。保留短操作音效。原始音频文件保留，但页面不再请求背景音乐。
- 共享背景由 2,644,914 字节 PNG 改为 294,578 字节 WebP，下载体积减少约 89%；原图保留，画面尺寸不变。
- 游戏选择页停止岛屿持续浮动，减少 Planarity、Mirror Rush 部分装饰动画，并取消相关游戏的背景模糊。保留移动、命中、攻击和提示反馈。
- KNN 内部画布最高 1280×720，不改变屏幕上的显示尺寸；不再每帧读取布局，改用尺寸观察；场景最多约 30 次/秒绘制，暂停/地图/解题时约 5 次/秒，隐藏时不绘制。原移动、碰撞和计时循环保留。
- Mirror Rush 的位置、进度与导弹等常规 React 画面更新限制为约 30 次/秒，物理与碰撞仍按原循环计算。
- 增加游戏加载/渲染错误边界，失败时显示可点击的 Reload games 恢复入口。它可以处理游戏模块加载失败和 React 渲染异常，不能保证捕获浏览器进程崩溃、所有事件异常或网络一直无响应。

## 验证

- `npm run lint`、`npm run build` 通过。仓库 lint 默认排除 digital-games，数字游戏源码由 Vite 构建及下述浏览器测试验证。
- `npm run test:digital-games` 通过：计分、短流程、结果桥接、玩家输入与闲置检测。
- `scripts/verify-digital-short-games-browser.mjs` 通过：六款介绍、Conway 培育和发球、数列通关、Planarity 胜者 QR、Mirror Rush 自然失败及领分；没有创建真实积分。该项运行于本轮游戏逻辑修改后。
- 扩展 `scripts/verify-digital-performance.mjs` 并通过：1920×1080、2 倍像素比下的 KNN 画布上限，无背景音乐请求，岛屿停止动画，游戏按需加载，结束后卸载，以及模拟模块下载失败后的恢复按钮。
- 二维码测试使用模拟服务器，不代表 MAXHUB 上的真实网络耗时，也不代表所有设备能达到 30 FPS。

## 下一步

重新部署后，在 MAXHUB 上强制刷新，再分别测试 `/games` 与 `/digital-play/index.html`。重点看：入口显示、KNN 移动、Mirror Rush 移动及各游戏返回后的稳定性。

如果仍然白屏或严重卡顿，收集 Console 最早的红色错误、Network 失败请求和设备浏览器版本。本轮是初步减负，不能代替实际设备定位。无需 SQL 操作。
